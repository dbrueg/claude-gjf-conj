# Lean formalization of GJF Conjecture 1.4

Lean 4 + Mathlib proofs of both halves of Conjecture 1.4 of Gaiotto–Johnson-Freyd,
*Holomorphic SCFTs with small index* (arXiv:1811.00589):

```lean
theorem GJF.conjecture_1_4 :
    (∀ (n : ℕ) (C : Submodule (ZMod 3) (Fin n → ZMod 3)), IsSelfDual C → 0 < n →
      (24 : ℤ) ∣ gjfIndex C) ∧
    (∀ k : ℕ, 1 ≤ k → ∃ C : Submodule (ZMod 3) (Fin (12 * k) → ZMod 3),
      IsSelfDual C ∧ gjfIndex C = 24)
```

`gjfIndex C` is GJF's definition taken literally: the number of even minus the number of odd
maximal codewords. A maximal codeword has no zero entry; its parity is the number of entries
equal to 1. `IsSelfDual C` says `x ∈ C ↔ x ⬝ᵥ c = 0 for all c ∈ C`. The hypothesis `0 < n` is
needed: at length 0 the empty word is an even maximal codeword, so the index is 1.

The code-level half of GJF's Main Question (Tier A of `../notes/blueprint/README.md`) is also
formalized, with one numerical seed value as a hypothesis:

```lean
theorem GJF.Ex.tierA (hE : Q8Z3.E72Hyp) (k : ℕ) (hk : 1 ≤ k) : MQcode k
```

`MQcode k` (in `GJF/TierA.lean`) asks for a self-dual code of length `12k` with index 24 and, with
`m = gcd(k, 24)`, the signed permutations in `Aut(C)` that GJF Thm 5.6 and the Q₈ results need:
`J² = -1` (m = 4); `g` of order `m` with `g^(m/2) = -1` and `h = g^(m/3)` fixed-point-free with
`T_h = 0` (m = 3, 6, 12); `Q₈` (m = 8); `Q₈ × ℤ/3` with `T_h = 0` (m = 24). The hypothesis
`Q8Z3.E72Hyp` is `R_σ(E₇₂) = 24` for the length-72 seed, a sum over 2³⁶ information-set patterns
that the kernel cannot do; it was checked by three independent programs
(`../ternary60/theory/mainq_e72_infoset.py`). Every other seed fact is checked by the kernel.

Theorem D of `../paper/conj14.tex` (an automorphism with `g⁴ = -1` forces `48 ∣ Index`) is
formalized as well:

```lean
theorem GJF.Obs.theoremD (C : Submodule (ZMod 3) (Fin n → ZMod 3)) (hC : IsSelfDual C)
    (hn : 0 < n) (g : Ex.SP (Fin n)) (hgC : g.Inv C) (h4 : g ^ 4 = -1) :
    4 ∣ n ∧ (48 : ℤ) ∣ gjfIndex C ∧ (Odd (n / 4) → gjfIndex C = 0)
```

`g` is a signed permutation (a monomial map) with `g C ⊆ C`. `GJF.Obs.theoremD_twelve` is the
paper's form (length `12k`, `Index = 0` for odd `k`), and `GJF.Obs.index_ne_24` the consequence
that a code of index `±24` has no such `g`.

Everything uses only the standard axioms (`propext`, `Classical.choice`, `Quot.sound`).
There is no `sorry` and no `native_decide`: finite checks are done by the kernel with `decide`.

## Files

| file | contents |
|---|---|
| `GJF/Divisibility.lean` | 24 \| Index (`GJF.index_dvd_24`). The signed 2-design `GJF.design` is proved by one Poisson summation over C with two marked coordinates. The factors 8 and 3 follow by counting arguments. This is route C of `../paper/divisibility.tex`. |
| `GJF/Existence.lean` | A code of index exactly 24 at every length 12k (`GJF.Ex.exists_selfDual_index24`), by partial Hadamard quadrupling from the ternary Golay code. This is Theorem 5.9 of the notes and `../paper/index24.tex`. Also contains `GJF.conjecture_1_4`. |
| `GJF/Orthogonal.lean` | `IsSelfDual C` is Mathlib's `C⊥ = C` for `dotProductBilin`, and is equivalent to "self-orthogonal and 2·dim C = n". Also gives the main theorem restated in that form (`GJF.index_dvd_24'`). |
| `GJF/Sanity.lean` | The tetracode is self-dual, so the hypotheses are satisfiable at positive length. |
| `GJF/SPerm.lean` | Signed permutations `SP X` (the monomial maps), their action, `Inv g C` (g ∈ Aut C), transport along equivalences, block permutations. |
| `GJF/LocalMaps.lean` | The group `LM` of order 8 of local maps on a block (a regular Q₈ in Aut of the tetracode), and the refinement identity `localBt` for the transposed split. |
| `GJF/Equivariant.lean` | Equivariant partial quadrupling: group data `SM` on a block state, its extension to the doubled code (`extD`), the step-one blocks (`step1`) and the refined state (`newSM`); all are monoid homomorphisms, so relations are inherited. |
| `GJF/Chain.lean` | Uniform chains: blocks `O × Fin 2`, one refined orbit per step, length `+24·|O|` per step (`ustate_chain`); `stage0` for the first step from a seed. |
| `GJF/ChainJ.lean` | The J-chain from Golay (`exists_J`, m = 4). |
| `GJF/Eval.lean` | A verified bit-sliced evaluator for seed sums: bitmask words, evaluation trees with pruning at information coordinates, soundness (`fastT_eq`), seed codes from bitmask rows (`R_seed`), sums over fixed codewords with a left-inverse certificate (`fixed_sum`, `comp_of_cert`), and splitting of a tree into separately checked chunks (`fastT_split`). |
| `GJF/ChainQ8.lean` | The Q₈-chain (`exists_Q8`, m = 8); the seed sum has 2¹² leaves. |
| `GJF/Twined.lean` | Twined counts: `T_h(Q_σ E) = R^h_σ(E)` (`Th_Qt`) and `R^h` of the next state (`Rh_NSt`), notes/blueprint/chains-and-seeds.md Lemma 2.3. |
| `GJF/SeedCert.lean` | `R^h`, `T_h` and the index of a seed as fast-tree values. |
| `GJF/SeedZ12Data.lean`, `GJF/SeedQ8Z3Data.lean`, `GJF/CertZ12*.lean` | Generated by `../ternary60/theory/lean_seed_data.py` (seed rows, placements, generators, trees, certificates; the `Cert` files split the ℤ/12 seed sums, 2¹⁸ and 2¹⁰·24² leaves, into chunks). |
| `GJF/ChainZ12.lean` | The ℤ/12-chains A and B and the k = 3 seed (`exists_Z12`, m ∈ {3, 6, 12}). |
| `GJF/ChainQ8Z3.lean` | The Q₈ × ℤ/3-chain (`exists_Q8Z3`, m = 24), given `E72Hyp`. |
| `GJF/TierA.lean` | `MQcode` and `tierA`. |
| `GJF/Obstruction.lean` | Theorem D (`GJF.Obs.theoremD`). The paper's proof without `𝔽₉`: `V₊ = ker(g² + g - 1)` and `V₋ = ker(g² - g - 1)` are isotropic with projector `g³ + g - 1`; for `v ∈ C ∩ V₊` and `w ∈ V₋` with `v·w = 1`, `D = C ∩ ⟨w, gw⟩^⊥` has `D^⊥ = C ⊕ ⟨w, gw⟩`, and the self-dual codes through `D` that carry maximal words are `C`, `D + ⟨w, gw⟩` and the graphs of `±L`, `L c = (c·w) gw - (c·gw) w` (`Setup.four_code`). Induction on `|C ∩ V₊|` gives `16 ∣ Index`; the cycle count (`orbit_count`) gives `4 ∣ n` and `f ∘ g = (-1)^(n/4) f`. A non-vacuity example: the tetracode with an element of order 8. |
| `GJF/Basic.lean` | A toolchain check: M₂(SL₂ℤ) = 0 and the Jacobi theta law. The proofs above don't use them. |

## Building

```bash
lake build                      # about 30 min on 4 cores (the ℤ/12 certificates `CertZ12*`); the rest about 5 min
```

To inspect the axioms, put this in a file that imports `GJF` and compile it with `lake env lean`:

```lean
#print axioms GJF.conjecture_1_4
#print axioms GJF.Ex.tierA
#print axioms GJF.Obs.theoremD
```

The toolchain is `leanprover/lean4:v4.35.0-rc3`, with Mathlib `master` pinned in `lake-manifest.json`.
In the cloud container, `release.lean-lang.org` and `cache.mathlib.org` are blocked. The toolchain
then comes from the GitHub release tarball, and the Mathlib cache from
`MATHLIB_CACHE_GET_URL=https://lakecache.blob.core.windows.net/mathlib4-master lake exe cache get`.
The step-by-step setup is in `../CLAUDE.md`.

## Notes for maintainers

- A Mathlib instance, `instAddCommGroupOfIsSimpleAddGroupOfIsNilpotent`, applies to `ZMod 3`.
  It takes over the search for `Neg (ZMod 3)`, and `simp` and `ring` then fail to match.
  `Existence.lean` removes it with `attribute [-instance]`.
- Mathlib's field lemmas, such as `finrank_orthogonal`, don't find instances for objects built
  with `ZMod 3`'s ring instances. `Orthogonal.lean` passes the instances explicitly.
- More pitfalls are listed in `../CLAUDE.md`. The mathematics is in `../notes/ternary-code-index.md`,
  §2 Step 1′ and §5.1(f‴).
